cz.mts.phone number-blocking rules

1. What can be added to the blocked items list

  • a) exact number – 602123456, +420602123456
  • b) mask – +420602* (* = any number of characters, ? = exactly one)
  • c) negative rule – !mask, e.g. !+420* = block everything that does NOT start with +420

Entries are stored as text in the system blocked-number store (BlockedNumberContract). The system never matches masks and negative rules against a real number (it only compares equality); they are evaluated exclusively by the app cz.mts.phone.

2. Evaluation order for an incoming call

  1. Hidden number (no number): only when "block calls for hidden numbers" or "block calls from numbers not in conatcts" is ON. The blocked list and negative rules do not apply.
  2. Blocked list. Blocking ALWAYS !!! (even if the number is in the contacts):
    • exact match with a stored number → block
    • match with a positive mask (* ?) → block
    • negative rules → block if the number matches none of them
  3. "Block calls from numbers not in conatcts" switch: blocks every number that is not in contacts.
  4. Otherwise the call goes through.

3. Negative rules !

  • Syntax: ! always in first position, followed by a mask. The mask after ! behaves like a regular mask.
  • Multiple negative rules → the number is blocked only if it matches NONE of them. Example: !+49* and !+420* let +49… and +420… through, everything else is blocked.
  • The number is compared in three forms:
    a) as received;
    b) digits only (with a leading "+" if there was one);
    c) E.164 (with country code number), if the libphonenumber library could validly convert it.
  • Negative rules are evaluated ONLY for numbers that libphonenumber can validly convert to E.164. What cannot be converted is not blocked and goes through: short and service numbers, codes like *123#, invalid numbers (including invalid numbers starting with +), spoofed numbers.
  • An exact number and a positive mask take precedence over a negative rule. A number matching them is blocked even if a negative rule would let it through.
  • Outgoing calls: negative rules are not applied. Exact numbers and positive masks apply to outgoing calls as before = a dialog is shown saying the number is blocked and the call cannot be made.
  • The prefix 00 is not converted manually. If the region is known (see section 4), it is converted to "+" automatically. If the region is not known, the number "cannot be converted" and goes through. You can, however, create an additional rule for the 00 form, e.g. !00420*.

4. Region (how the country code is determined for numbers not starting with "+")

Order:

  1. country stored in the SIM that receives the call
  2. country of that SIM's network
  3. default SIM / phone network (only when the specific SIM cannot be determined)
  4. phone language – last resort

Of course, for numbers with "+" in first position the region does not need to be determined.

The phone language can therefore only come into play when the SIM cannot be determined (accountHandle == null, missing READ_PHONE_STATE permission …), which in practice will probably never happen…

5. Entry in the dialog and import

Allowed: digits, *, ?, + (only at the start or right after !), ! (only as the first character). Other characters are discarded. A negative rule must contain at least one digit (otherwise e.g. "!?" would block almost everything). The JSON import performs the same check. An entry with "!" is treated as a mask (type "pattern") on both import and export.

6. Known limitations

  • A number that libphonenumber considers invalid (wrong digit count, a spoof such as +1 555 555 0123) is not blocked by negative rules. Positive masks do catch it (example D in the table).
  • When the region cannot be determined (see section 4), numbers written nationally or with 00 go through because they are not converted. Language "en" without a country behaves like en_US.
  • Deleting and saving masks containing * ? ! in the system store is somewhat fragile: it depends on the specific vendor's implementation, and it may happen that they cannot be inserted into the store at all.
